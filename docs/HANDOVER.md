# Wamumbi: handover

How the site fits together, how to run and deploy it, and what is still open. Read this first; the rest of `docs/` goes deeper.

Live: https://wamumbi-red.vercel.app (custom domain to come, see [Open items](#open-items)).

## At a glance

| | |
|---|---|
| App | Next.js 15 (App Router), React 19, TypeScript, in `web/` |
| Styling | Tailwind 3 with HSL tokens in `src/app/globals.css`; dark theme is the default. Design rules: [`DESIGN.md`](../DESIGN.md) |

| Payments | M-Pesa till 8392352 shown on `/donate`. No online payments yet (by decision) |

## Run it locally

```bash
cd web
npm install            # also runs prisma generate
vercel env pull .env.local   # or copy the variables below by hand
npm run dev            # http://localhost:3000
npm test               # 347 RBAC tests
npm run lint
```

Apply database migrations (uses the direct, non-pooled Neon host):

```bash
npx prisma migrate deploy --config prisma/migrate.config.ts
```

## Environment variables

| Name | What it's for | Required |
|---|---|---|
| `DATABASE_URL`, `DATABASE_URL_UNPOOLED` | Neon connection (set by the Neon integration) | Yes |
| `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY`, `CLERK_SECRET_KEY` | Clerk. Both must come from the **same** Clerk instance | Yes |
| `SUPER_ADMIN_EMAILS` | Comma-separated emails that become Super Admin on sign-in | Yes |
| `BLOB_READ_WRITE_TOKEN` | Photo uploads (set by the Blob store) | For uploads |
| `RESEND_API_KEY`, `NOTIFY_EMAIL`, `NOTIFY_FROM` | Email alerts for new volunteer/partner submissions | Optional |
| `NEXT_PUBLIC_SITE_URL` | Absolute links in those emails | Optional |

Never commit `.env*` files; they are gitignored.

## How the code is organised (`web/src`)

- `app/`: routes. Public pages (`/`, `/about`, `/events`, `/events/[id]`, `/events/past/[slug]`, `/gallery`, `/campaigns`, `/donate`, `/volunteer-signup`, `/partner-with-us`, `/terms`, `/privacy`), auth (`/sign-in`, `/sign-up`, `/profile`), and staff pages (`/dashboard`, `/dashboard/campaigns`, `/dashboard/events`, `/dashboard/admin`, `/donations`, `/volunteers`, `/projects`, `/reports`).
- `components/`: `page-shell.tsx` (public page frame), `dashboard/shell.tsx` + `dashboard/ui.tsx` (dashboard frame and building blocks: stat strip, panel, table toolbar, side sheet, status, progress), `dashboard/views/` (one file per dashboard page), `auth/` (Clerk theming), `motion.tsx` (`Reveal`, `CountUp`).
- `trpc/`: one router per area. `trpc.ts` defines `publicProcedure`, `optionalAuthProcedure`, `protectedProcedure`, `permissionProcedure(...)`.
- `lib/rbac/`: roles, permission matrix and response redaction. Change permissions here, then run `npm test`.
- `server/`: current user, approval workflow (`review.ts`), audit log, email notifications.
- `data/`: past events and gallery photo index (generated by `scripts/process-media.mjs`).

## Rules that keep it safe

- **The server decides.** Every procedure uses one of the procedure helpers; UI checks only hide buttons. New procedures must use `permissionProcedure` (or `protectedProcedure` with an explicit ownership check).
- **Never trust IDs from the browser for "who is acting".** Use `ctx.user.id` (registration and donations were fixed for exactly this).
- **Unpublished content stays hidden.** Campaign and event lists show drafts and items awaiting review only to staff; non-admins' new content goes to **Dashboard → Admin → Approvals**.
- **Builds fail on type and lint errors.** Fix them; don't switch the checks off.

## Deploying

- Push a branch and Vercel builds a preview (protected by Vercel login). Merging to `master` deploys to production automatically.
- A GitHub Action (`.github/workflows/delete-merged-branch.yml`) deletes a pull request's branch when it's merged. With **Neon → Integrations → Vercel → Branches → Automatically delete obsolete branches** on, the matching preview database goes too. The free plan allows 10 Neon branches.
- New database changes: add a Prisma migration in `prisma/migrations/` and run `migrate deploy` against production before merging code that depends on it.
